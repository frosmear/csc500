Loops are useful when a program needs to repeat an action on multiple objects with little to no variation. 
The essential parts of a loop are the starting value or initialization, a condition that determines whether the loop should continue, 
and some form of change or increment that eventually allows the loop to stop. The exact structure depends on whether the loop is 
count-controlled or condition-controlled.

An example of a count-controlled (definite) loop would be counting the number of files in a folder or iterating through a list of new videos 
that need to be added to my collection. In this situation the program  has a known group of items to process, so a for loop works well. 
The loop can go through each file or video, run my ffmpeg script to preconvert them for my kids tablets and then stop wasting electricty
when there are no more.

An indefinite (condition-controlled) loop is useful when the number of repetitions is not known ahead of time. I have used this type of loop when 
dealing with user inputs, like the youTube downloader. The program can continue asking for input until the user provides something valid, which is 
especially useful for handling the tricks Google does to thwart that (and force my kids to watch ads).  A while loop is a good choice because the 
program does not know how many attempts will be necessary.

Pseudocode for validating user input could look like this:

WHILE True
    Parse the new URL
    IF the URL downloads
        Save the video locally
        Parse metadata, add to my database
    ELSE
        Note in the log it failed
        Continue to next item
    Sleep 10 seconds waiting for a new URL

The loop is controlled by a condition rather than a predetermined number of repetitions. Once the user enters valid information, the condition changes 
and the loop does something.  In this case it's infinite (or until power cycled) but the sleep avoids burning CPU.
