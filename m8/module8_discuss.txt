The easiest way for me to understand the difference between a class and an instance is to think of a class as the blueprint and the instance as the thing that gets built from it. The class defines what something is supposed to have and do, while an instance is an actual object created from that definition.

For example, if I made a `Song` class, the class could define a title, a list of subjects, and a function for singing the song. I could then create different instances of that class for different songs.  In the real world hackers can and will distort them for good, bad, and ugly outcomes.

This reminds me of The Lonely Island's "Jack Sparrow" song, where Michael Bolton keeps hijacking the song to sing about completely different movies. For this example, the instances could be the different movies Bolton decides the song is about.

```python 
class Song:
    def __init__(self, title, movies):
        self.title = title
        self.movies = movies
        self.__goal = "Prevent Bolton from changing the song"

    def sing(self):
        print(f"Singing {self.title}")
        for movie in self.movies:
            print(f"Bolton is singing about {movie}")


# Create an instance of the Song class
jack_sparrow = Song(
    "Jack Sparrow",
    ["Pirates of the Caribbean", "Forrest Gump", "Erin Brockovich", "Scarface"]
)

jack_sparrow.sing()
```

In this example, `Song` is the class and `jack_sparrow` is an instance of that class. The class is the blueprint, while `jack_sparrow` is the actual object created from it.

The `__goal` attribute is what I would consider a hidden attribute. In Python, putting two underscores at the beginning of an attribute name causes Python to name-mangle it so that code outside the class cannot access it using the normal attribute name. It is not absolute security, but it is a way of indicating that the attribute is intended to be private to the class.

In this completely necessary example, the goal is to prevent Bolton from changing the song. Unfortunately, given the source material, I am not sure even encapsulation is going to stop him. 

For me, the useful part of OOP is that the class lets me define the structure and behavior once and then create multiple instances from it. Each instance can have its own data while still following the same blueprint. The hidden attribute gives the class a way to keep certain internal information from being casually changed by the code using the object.
